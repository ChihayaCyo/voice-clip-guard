# Voice Clip Guard

Windows 语音输入兜底工具：**按一下「整理键」，把当前输入框里的完整文本抢救进剪贴板 + 本地日志。**

用来防这一类事故：豆包输入法 / 微信输入法在「智能整理」阶段偶发把已经输入好的整段文字搞丢（原文被删、整理结果没回来，剪贴板里也没有）。

## 背景

实测（Windows 11 + 豆包输入法 v1.0.0.23）：

- 豆包通过 `tsf-oime-core.dll` 走 **TSF 编辑会话**（`RequestEditSession` / `SetText`）上屏，**不产生键盘事件、不经过剪贴板**，所以普通键盘钩子拦不到，也偷不到。
- 丢字发生在**输入完成、按整理键之后**的 AI 整理环节，而不是输入过程中。
- 一旦丢掉，本地日志是加密的（字节 `alog` 格式）、输入法内存里也已释放，**无法恢复**。

所以兜底必须发生在「按整理键的那一刻」。

## 原理

```
按键钩子(WH_KEYBOARD_LL)  ──检测「整理键」──▶  读取当前焦点输入框全文(UIA)
                                                    │
                                    ┌───────────────┴───────────────┐
                                    ▼                               ▼
                              剪贴板（立即可粘）            按日日志（永不覆盖）
```

- **不轮询**：平时完全不查其他应用，因此不会激活 Chromium 的 accessibility 树，也不会让 Electron 应用（如某些编辑器/IM）卡顿。
- **按键触发**：只有按下你指定的「整理键」时才读一次。
- **双采样**：按下瞬间读一次、350ms 后再读一次，取更完整的版本（语音识别是流式的，末尾标点可能晚到）。
- **占位符防护**：优先用 `ValuePattern`；输入框为空时直接返回空，**不回退**到 `TextPattern`——否则会读到输入框的占位提示（placeholder），把真实内容挡住。
- **去重**：与上次写入完全相同的内容不再重复写剪贴板，避免剪贴板历史堆满重复项。

## 环境要求

- Windows 10 / 11
- .NET Framework 4.8（系统自带）
- 编译只需系统自带的 `csc.exe`，不依赖 Visual Studio / dotnet SDK

## 编译

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
# 产物：dist\VoiceClipGuard.exe
```

## 使用

1. 运行 `dist\VoiceClipGuard.exe`，托盘出现图标。
2. 右键托盘图标 → **学习「整理键」** → 5 秒内按下你平时按的那个键（例如右侧 Alt）。
3. 之后正常用语音输入：说完 → 按整理键 → 完整文本自动进剪贴板 + 日志。

托盘菜单项：

| 菜单项 | 说明 |
|---|---|
| 学习「整理键」 | 重新录制触发键（5 秒内按一次） |
| 手动兜底一次 | 立即复制当前输入框全文 |
| 暂停 / 继续 | 临时关闭监听 |
| 重新复制最近一次兜底内容 | 剪贴板被其他复制覆盖后找回 |
| 打开日志目录 | 查看历史捕获 |
| 退出 | 退出程序 |

数据目录：`%USERPROFILE%\voice-clip-guard\`

- `YYYY-MM-DD.log`：每次捕获的全文（追加式）
- `guard.log`：运行日志（每次触发读到的字数、跳过原因等）
- `settings.json`：已学习的触发键

## 覆盖范围

只要目标输入框向 **UI Automation** 暴露文本即可命中：

| 应用 | 结果 |
|---|---|
| 记事本（RichEditD2DPT） | ✅ |
| Chromium 系（Chrome / Edge / Electron 且启用了 accessibility） | ✅ |
| 标准 Win32 Edit / RichEdit 控件 | ✅ |
| Obsidian 等未启用 accessibility 的 Electron 应用 | ❌ UIA 树为空 |
| 自绘 UI 的 IM（如微信 4.x） | ❌ 不暴露文本 |

对 UIA 读不到的应用，本工具无能为力（这不是工具实现问题，是应用没暴露文本给系统）。

## 注意

- `%USERPROFILE%\voice-clip-guard\*.log` **包含你语音输入的全部内容**，注意隐私与磁盘占用；不需要时可直接删除。
- 触发键通过键盘钩子（`WH_KEYBOARD_LL`）识别，只读不拦截，不会影响该按键原有功能。
- 单实例运行：重复启动不会起第二份。
